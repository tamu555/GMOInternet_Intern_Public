# トップページ デザインテーマ候補

ドメイン検索画面（トップ）だけを 14 案作成した、静的HTMLのモックです。
1案を選んでいただければ、その配色・書体・レイアウト規則を `frontend/DESIGN_SYSTEM.md`
に落とし込み、他の画面（申込フォーム・マイページ・会員登録）へ展開します。

## 全案に通した基本方針

| 論点 | 対応 |
|---|---|
| ヒーローの構図 | 案ごとに作り分け（左揃え・中央揃え・2カラムを混在させ、テンプレート化を避ける） |
| ✨スパークル付きピルバッジ | 使用しない |
| アイコン＋短文の特徴3点の横並び | 使用せず、全22TLDの初年度・更新料という実データに置き換え |
| 意味を運ばないスローガン | 使用しない（「個人でも法人でも。選べるTLDラインナップ」等） |
| 角丸・影 | 案ごとに1〜2種類へ統一 |
| 書体 | 案ごとに性格の異なる組み合わせを指定（明朝／等幅／Didone／丸ゴシック 等） |

アプリ名は全案 **TeamC.Com** に統一しています。

## 挙動のあるモック

- **3 / 4 / 5 / 14**: ヘッダーを固定表示（スクロールしても上に残ります）。3 はヒーローに重ねているため、
  スクロールすると背景が入る仕様です（`.scrolled` クラスをJSで付与）。
- **4**: 最初の1画面をヒーローの緑だけで埋めます（`min-height: calc(100vh - 66px)`）。
- **12**: 見出し「名前をひとつ入れて、22TLDを一度に調べる。」を1文字ずつ表示します（ブロックカーソル付き、
  一定時間後にループ）。`prefers-reduced-motion: reduce` の環境では即時表示に切り替わります。
  本文フォントもピクセルフォント（DotGothic16）へ統一しました。


## マイページの「育つ木」

トップページとは別に、マイページ用のイラスト（保有ドメインが増えるほど木が育ち、葉の1枚1枚が
ドメインを表す）を検討中です。

| ファイル | 内容 |
|---|---|
| `_mypage-tree-proto.html` | 初期案。葉に名前を直接書く1案のみ、アニメーションなし |
| `_tree-variants.html` | 方向性の違う5案（大樹／実のなる木／盆栽／ドット絵／放射の樹形図）。アニメーション付き |
| `_top-tree-preview.html` | トップページ右カラム（HeroArt）を育つ木に置き換えるプレビュー。成長5段階＋葉にドメイン名、読込中/失敗/未ログインの分岐、コンパクト表示つき |
| `_top-tree-growth.html` | **最新案**。木を手描きせず取得件数から毎回その場で生成し、葉が茂って生きものが集まる。現行トップ（角丸ゼロ・白ヘッダー・ゼロからドメイン）に合わせて写経済み |
| `_tree-cartoon-domains.html` | **葉＝1ドメインの最新案**。ヒーローのイラストに寄せた淡いセージ調の木。葉にホバー／Tabでドメイン名が出て、色＋記号が状態を、落ち葉が失効を表す |
| `_tree-markers.html` | **マーカー案の最新**（2026-08-28）。ドメイン1件＝1つのマーカーで、**形が「期限までの距離」**を表す。余裕あり＝熟した実／ちょうちょ／地面の花、期限が近い＝かたつむり（31〜90日）とはち（30日以内）、期限切れ＝地面の枯れた花。プレミアムTLDは金の実＋きらめき。木の下の「この木について」で対応表が開く |

### `_tree-markers.html`（マーカー案）

本番の「ドメイン＝葉」が浮いて見える原因は3つあり、効いているのは3つ目です。
水彩のテクスチャの上に無地の面を置いていること、輪郭がベクターのまま硬いこと、そして
**葉の上に葉が乗るという状況が自然界に無い**こと。生きもの・木の実・花は3つ目を最初から
満たすので、同じベタ塗りでも「乗っている」と読めます。

**マーカーの形は「期限までの距離」を表します。**

| 帯 | マーカー | 置き場所 |
|---|---|---|
| 余裕あり（91日以上） | 熟した実 / ちょうちょ / 地面の花 | 葉・葉・地面 |
| 期限が近い（31〜90日） | かたつむり | 幹 |
| 期限が近い（30日以内） | はち（羽音が速く色が濃い） | 葉のそば・飛 |
| 期限切れ・失効中 | 枯れた花 | 地面 |
| 期限が分からない | てんとう虫 | 葉 |

**プレミアムTLDは形ではなく素材で示します。** 余裕がある帯では実が金色になり、
どの帯でもマーカーのまわりが小さく光ります（`SPARKLE`）。形を専用のものに変えないのは、
形の軸が期限だからです — プレミアム専用の形を作ると、意味の軸が2本ぶつかります。

**木の下に「この木について」があります。** 押すと対応表がダイアログで開き、
「ドメインを取得すると、この木に実や生きものが増えます」という説明と、
どのマーカーが何を意味するか・どこに出るか・いま何件あるかが出ます。未ログインでも
読めるので、取得前の人にも「取ると木がこうなる」が伝わります。

しきい値は本番の `expiryIndicatorClass` と同じ **30 / 90日**。§3.5 の `ending`
（解約手続き中・いまなら復旧できます）は残り日数に関わらず失効側へ寄せています —
手続きが始まっている以上、日数が残っていても失われかけているためです。

**余裕がある帯の3種はドメイン名のハッシュで決まる**ので、同じドメインは毎回同じ姿に
なります。配分は 実14 : ちょうちょ4 : 花2。実を厚くしているのは、地面と飛ぶものが
増えると樹冠が薄くなり「実っている木」に見えなくなるためです。

⚠ **§3.5 のステータス（未公開・引っ越し中・ロック中・一時停止中）は形に出していません。**
形の軸を期限に一本化した結果で、これらは吹き出しと `aria-label` の文言でのみ伝わります。
一時停止中（clientHold）はサイトが止まっている状態なので、ホバーしないと気づけないのは
弱点です。必要なら小さな添え記号を足せます。

置き場所は絵から割り出しています。

| | 出し方 |
|---|---|
| 葉 | 緑優勢（G≧R）の画素を侵食してから最遠点サンプリング |
| 幹・主枝 | 赤優勢の画素。侵食を強めにして細枝を落とす |
| 地面 | 絵の外なので手置き。奥は小さく手前は大きく |

設計で効いているのは影の扱いです。**留まるもの（実・かたつむり・花）だけが接地影を持ち、
飛ぶもの（はち・ちょうちょ）は影を下へ離してぼかします。** 接地影の有無が
「乗っている / 浮いている」をほぼ決めます。生きものは**枝の向きに回しません** —
虫は葉の傾きに関係なく上を向くので、葉と同じように回すと途端に貼り付けたように見えます。
地面の株は足もとを基準に拡大します（中心基準だと指した瞬間に土から浮く）。
幹は細い縦帯なので、**置いたものから一定距離離れるまで候補を送る**処理を入れています
（順番に取るだけだと かたつむり が縦に重なりました）。

作る途中で捨てた案が3つあります。**青い実**（未公開）は樹冠の緑に埋もれて見つけられず、
**輪郭線だけで描いた殻**はドーナツにしか見えず、**帽子と実を離して描いたどんぐり**は
器と蓋に見えました。いずれも実際に置いて拡大して初めて分かったものです。

LottieFiles は環境から取得できず（403）、また外部アセットはライセンスと帰属表示の確認が
要るため、マーカーはすべて自作の SVG + CSS です。

`_tree-variants.html` は上部のスライダーが5案すべてを同時に動かします。0件から20件まで
動かして、増えかたの違いを同じ件数で見比べてください。配色・書体は `theme-04-3-wakakusa`
のトークンをそのまま使っているので、選んだ案はそのまま `frontend/` に移せます。

葉の色は4状態（取得したて／通常／更新が近い／期限切れ）を運びます。木は要約であって一覧の
代わりではないので、本番ではどの案でも下にドメイン一覧を置く前提です。

`_top-tree-preview.html` は「実のなる木」案をトップページ向けに調整したものです。右下の
コントロールで件数（0〜24）・長い名前・読込中・失敗・未ログイン・アニメ軽減を切り替えられ、
`?n=20&mode=error` のようにURLでも状態を指定できます。木と葉は自作SVG/CSSのみで、外部
イラスト素材は使っていません（Storyset の木はSNSロゴ入りの単一パスで不採用と判断）。

### `_tree-cartoon-domains.html`（葉＝1ドメイン・ホバーで名前）

`_top-tree-growth.html` が「葉の量で件数を語る」案なのに対し、こちらは **葉1枚＝ドメイン1件** に
戻した案です。名前を葉に焼き付ける代わりに、**ホバー／フォーカスでツールチップに出します**。
絵柄はアプリのヒーローにある淡いセージ調の木に合わせてあります。

- **樹冠は房の集まり**。幹から再帰で枝を伸ばし（枝は等幅ストロークではなく塗りパスでテーパー）、
  枝先ごとに小さな葉の粒を集めた房を置く。房は5トーンで、光は左上から当たる想定
- **ドメインの葉を置く座標は実行時に決まる**（`pickSlots()`）。実際に生成された房の中から、
  幹の真上と暗い房と樹冠のふち5%を除いて、最遠点順に24か所。座標を手で持つと樹冠を作り直す
  たびに葉が空中へ取り残される
- **状態は色だけで伝えない。** 葉の上に記号のグリフ（✦ ● ◐ ▲ ✕ ？）を描く。樹冠の緑と葉の緑は
  実測で最悪 1.04:1 まで落ちるので、塗りでは状態を伝えきれない。葉のふちには常時ハローを引く
- **期限切れの葉は落ちて根もとに残る**。落ちた葉もホバーできる（何が失効したのか後から読めないと、
  落ち葉はただの飾りになる）
- 背景の淡いブロブ・舞い落ちる装飾葉・根もとの草を別レイヤーで持つ。装飾葉は `pointer-events:none`
  で、ドメインの葉のホバーを邪魔しない
- 右下のコントロールで件数（0〜24）・＋1件取得・状態を1つ進める・1枚を期限切れに・アニメ軽減・
  配色（若草／参考画像）を切り替えられる

#### ここで踏んだ罠（実装時に効くもの）

- **落下中に再描画すると `animationend` が二度と来ない。** `innerHTML` の総入れ替えで要素ごと
  作り直されるため、着地処理が走らず葉が宙ぶらりんで木に残る。落下中の葉は `items` から外して
  `falling` で持ち、着地は `setTimeout` で確定させる。再描画時は経過ぶんだけ `animation-delay` を
  負にして続きから再生する
- **SVG 要素の `transform-origin` の既定は viewBox の原点。** `.fall` に指定を忘れると、葉が
  その場で回らず viewBox の左上を軸に大きな弧を描いて画面外へ飛ぶ
- **`innerHTML` の入れ替えで `mouseleave` は来ない。** ツールチップが出っぱなしになり、
  `document.activeElement` は body に落ちる。再描画のたびに両方拾い直す
- **ツールチップは `z-index` を sticky ヘッダより上に。** 上に置けない葉は下側へ反転させる
- **葉24枚をそれぞれタブ止まりにしない。** roving tabindex で葉むら全体を1タブ止まりにし、
  中は矢印キーで移動する

### `_top-tree-growth.html`（最新案）

前案との違いは、**木が決め打ちの絵ではないこと**です。段階ごとのSVGを差し替えるのではなく、
取得件数から再帰で枝を生やし、樹冠と葉をその場で組み立てています。

- 件数 → 成長段階（種／芽／若木／木／大きな木／大樹）→ 枝の再帰深さ・幹の長さ・葉の量
- **葉は1枚ずつドメインに対応させません。** v1では対応させましたが、名前は小さくて読めず、
  それでいて葉が増えないので樹冠がすかすかになりました。いまは「葉の量」で件数を語り、
  件数そのものは木の下の数字（`24 件のドメインが育っています`）で見せています
- 更新が近い分・期限切れの分は、その割合だけ葉の色を橙／茶に差し替えて気配だけ伝えます
- **育つほど生きものが増えます。** かたつむり（種）→ てんとう虫（芽）→ ちょうちょ（若木）
  → 小鳥・きのこ（木）→ りす・はち（大きな木）→ うさぎ・巣（大樹）。大樹がいちばん賑やか
- 形は seed で決まる。`?seed=31` のように差し替えて見比べられる（既定は **88**）

#### 期限の状態を葉で語る

- **更新が近い** → その持ち分の割合だけ葉が **黄色** く色づく（枝に残る）
- **期限切れ** → 一部は **枯れて茶色くなり、重みで下を向く**。残りは **落ち葉** として
  根もとに溜まり、さらに数枚が舞い落ちてくる
- 件数そのものはキャプション（`更新が近い 3件` / `期限切れ 1件`）が持っているので、
  絵の側は「気配」だけを伝える。葉1枚＝ドメイン1件ではない

#### 樹冠の作りかた（ここが肝）

枝の線に沿って葉を置くと、枝と枝のあいだが空いて樹冠が割れて見えます。そこで

1. 枝から葉の取りつけ位置を取り出す（枝先＋外側4世代の枝の途中。**幹には付けない** —
   付けると浅い木で樹冠が幹まで降りてきて「地面から生えた茂み」になる）
2. それを最遠点順にまとめて **葉むらのかたまり** を作る。半径は「いちばん近い
   かたまりまでの距離 × 1.32」＝ 必ず隣と重なるので、樹冠がひと続きになる
3. かたまり同士が離れかけていたら、あいだに小さなかたまりを **橋渡し** する。
   さらに樹冠の中心が空いていたら1つ足す（放っておくとハート型に割れる）
4. かたまりを暗い2色で塗りつぶす。**輪郭は楕円ではなく、半径を揺らした多角形を
   Catmull-Rom で丸めたブロブ**（きれいな弧のままだと「雲の絵」に見える）
5. その上に葉を散らす。かたまりの半径の 1.18 倍まではみ出させて輪郭をぎざぎざに

半径の上下限は木の広がりに比例させています。固定値にすると、若木の樹冠だけ体に対して
巨大に膨らみました。幹の根もとには **根張り** を足しています（まっすぐだと棒に見える）。
いちばん外側の小枝は描きません（葉むらより外へ出て枯れ枝に見えるため）。

#### 生きものの描きかた

円と楕円を貼り合わせると、つなぎ目が出て「幾何図形の組み合わせ」に見えます。
**体・頭・尾はひと続きの輪郭パス**で取り、その上に翼・耳・目などを重ねています。
外部のイラスト素材は使っていません（下記の調査結果を参照）。

#### 描画の重なり順

もや → 枝 → 樹冠の塗り → 葉（奥）→ 葉むらの中の生きもの → 葉（手前）→
樹冠の上の生きもの・飛ぶ生きもの、の順です。`<g>` はあとから append すると必ず前へ
出るので、**空のグループを先に並べてから中身を入れています**。

右下「試作コントロール」で件数・+1件取得・読込中／失敗／未ログイン・アニメ軽減・別の木を
切り替えられます。下段には成長段階の一覧と生きもの図鑑（どちらも同じ生成器で描画）。

#### 外部イラスト素材を使うか（調査済み・2026-08-27）

「動物や花はサイトからイラストを持ってくるのもあり」という案について調べた結果、
**(a) 商用可 (b) 表記義務なし (c) CSS で色を変えられる多パスSVG (d) 実際に鳥・りす・
うさぎ・ちょうちょ・はち・てんとう虫・かたつむりが揃っている** の4つを同時に満たす
配布元は見つかりませんでした。

| 候補 | ライセンス | 表記 | 動物 | 色替え |
|---|---|---|---|---|
| unDraw / ManyPixels / Lukasz Adam | 独自・実質CC0 | 不要 | **無い**（人物と場面のみ。rabbit / butterfly / squirrel / ladybug は検索0件） | ◯ |
| Storyset (Freepik) | 独自 | **必要** | ちょうちょ・うさぎ・はち・小鳥はある。りす/かたつむり/てんとう虫は無い | △（inline style） |
| DrawKit | 独自 | 不要 | 小鳥・うさぎのみ | ◯ |
| OpenMoji | CC BY-SA 4.0 | **必要＋継承** | **7種すべてあり** | ◎（`fill` 属性・線画版あり） |
| Twemoji | CC BY 4.0 | **必要** | 7種すべてあり | ◯ |
| Noto Emoji | Apache 2.0 | NOTICE同梱のみ | 7種すべてあり | △（inline style） |

現状は **自前SVGのまま** にしています。ライセンス管理も表記も不要で、ライト/ダーク両対応の
色替えがトークンだけで効くためです。もし差し替えるなら、表記が footer 1行で済む
**Noto Emoji (Apache 2.0)** か、線画を `currentColor` に置ける **OpenMoji の black 版** が
現実的な候補です（どちらも `LICENSES.md` を素材フォルダに同梱すること）。

#### 実装時の注意（このプレビューで踏んだ罠）

- SVG要素の `transform` **属性** は CSS の `transform` に上書きされて消える。揺れ・芽吹き・
  落ち葉・羽ばたきのアニメーションは、座標を持つ `<g>` とアニメを当てる `<g>` を必ず分ける
- 木の高さは段階でまるごと変わるので、描画後に実測して viewBox の上の余白を切り落とす。
  切り直したら、その値を見ている側（生きものの配置％など）も同じ値を参照すること
- 状態クラス（`is-loading` / `is-guest` / `is-error`）は `.tree-card` に付ける。
  `.tree-stage` に付けると、兄弟である件数キャプションを隠せない

## 実装時に守る契約（14案とも維持済み）

テストが完全一致で参照している文言・構造は、モックでもそのまま残しています。

- 見出し `ドメイン検索`（h1。多くの案では大見出しの上の小さなラベルとして配置）
- ラベル `取得したいドメイン名`、送信ボタン `検索する`（可視ラベル。aria-label 頼みにはしていません）
- ヒント文 `TLD（.com など）は含めず入力してください。全角文字は自動的に半角へ変換されます。`
- ヘッダーの `AuthContext: 未認証` 表示、`ログイン` / `会員登録` / `管理画面へ` のリンク名
- 検索結果の3状態は ◯ 空きあり / ✕ 使用中 / ？ 確認できませんでした を色 **＋記号＋文字** で区別
- 初年度と更新の金額は同じ文字サイズ（spec §6.2.5）

料金は `frontend/src/features/domains/tldData.ts` の値をそのまま使用しています
（同ファイルどおり、演習用のダミー価格です）。

## 選定後の進め方
