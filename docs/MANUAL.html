ゼロからドメイン 取扱説明書

ドメインを探して取得し、ホームページやメールにつないで管理するサービス「ゼロからドメイン」の使い方です。第1部が本体の取説、第2部が会員登録時の認証コードを確認する付属アプリ「Zerokara Mail」の取説です。

できること探す・取る・つなぐ・管理する22 種類の末尾で空きを調べ、1〜5 年で申し込み、DNS を設定し、更新や移管もできます
必要なものブラウザだけ会員登録には @example.com などのアドレスと、認証コード確認用の Zerokara Mail
お金はかかりません決済・料金・レジストリはすべて演習用の疑似的なものです
Part 1

ゼロからドメイン（本体）

ドメインを探して、申し込んで、つないで、管理するまで。ブラウザだけで使えます。

1これは何？

「ゼロからドメイン」は、自分だけのドメイン（example.com のような Web 上の住所）を探して取得し、ホームページやメールにつなぎ、期限を管理するための Web サービスです。ブラウザで開くだけで使え、インストールは要りません。

できること

  • 22 種類の末尾（.com .net .xyz …）で空きを一度に調べる
  • 1〜5 年分をまとめて申し込む・更新する（自動更新も可）
  • ホームページやメールにつなぐ（ネームサーバ／DNS 設定）
  • 他社からドメインを引っ越してくる・他社へ出す（移管）
  • 使われている名前が空いたら知らせてもらう（空き待ち）
  • 質問に答えるだけで進める「かんたんモード」と、画面内の AI アシスタント

できないこと・知っておくこと

  • 本物のお金は動きません。決済はすべて疑似決済です
  • 接続先のレジストリ（Kitaqsign / Kitaqnic）は演習用の疑似レジストリで、料金もダミーです
  • メールは一切送られません（認証コードは Zerokara Mail で確認します）
  • パスワードの再設定、アカウントの削除は画面から行えません
このサービスは学生ハッカソン（GMO インターネットグループ TeamC）の演習用です。実際のドメインが取得されることはありません。

3アカウントを作る

ヘッダーの「会員登録」から。5 ステップで、途中に 6 桁の認証コードの確認があります。

使えるメールアドレスについて：このサービスでは安全のため @example.com @example.net @example.org のアドレスだけが登録できます（実在のアドレスには何も届きません）。@ の前は自由です。
  1. 1

    アカウント情報を入れる（新規登録）

    氏名、フリガナ、メールアドレス、パスワード（8 文字以上 128 文字以内）、パスワード確認を入力し、「利用規約に同意します」にチェックして「新規登録」。

    すでに登録済みのアドレスだと、この時点で「このメールアドレスはすでに登録されています。ログイン画面からお進みください。」と出ます。その場合はログインへ。

    「Google でサインイン」を選ぶと、ステップ 2 を飛ばしてステップ 3 相当の情報入力画面（追加情報）に進みます。

  2. 2

    認証コードを入れる（メールアドレスを確認してください）

    「あなたのアドレス 宛の認証コードを発行しました。6桁のコードを入力してください。」と出ます。コードは本物のメールでは届きません。付属の確認アプリ「Zerokara Mail」（第2部 使い方）で同じアドレスを登録すると、受信トレイにコードが表示されるので、コピーして貼り付け、「認証する」を押します。

    • コードの有効期限は 10 分。間違えられるのは 5 回まで
    • 「認証コードを再送する」は 60 秒に 1 回。期限切れや回数超えのときはこれで作り直します
    • アドレスを打ち間違えたら「メールアドレスを変更する」でステップ 1 に戻れます
    • 認証が済むと 30 分間は次のステップに進めます。それを過ぎたらやり直しです
  3. 3

    契約者情報を入れる

    ドメインの登録者として記録される情報です。

    • 基本情報：契約者種別（個人／個人事業主／法人）、氏名、フリガナ、生年月日、性別、お知らせメールの希望
    • 会社情報（個人事業主・法人のみ）：会社名または屋号、部署名（任意）、担当者名
    • 住所情報：電話番号、居住国。日本なら郵便番号・都道府県・市区町村・番地・建物名（任意）

    「確認画面へ」で次へ。「戻る」で前に戻れます。

  4. 4

    入力内容の確認

    各項目の「編集する」でステップ 3 に戻って直せます。「この内容で登録する」を押した時点でアカウントが作られ、そのままログイン状態になります。

  5. 5

    登録が完了しました

    「マイページへ」で完了です。かんたんモードの途中で登録した場合は「かんたんモードの続きに戻る」も出ます。

4ログイン・ログアウト

  • ヘッダーの「ログイン」→ メールアドレスとパスワードを入れて「ログイン」。Google で登録した人は「Google でサインイン」。
  • 間違えると「メールアドレスまたはパスワードが違います。」と出ます。安全のため、どちらが違うかは表示しません。
  • ログイン状態は 5 日間保たれます。ログアウトはヘッダー右の「ログアウト」。
  • ページを開いたときに「ログイン状態を確認できませんでした。」と出たら通信の問題です。「再確認する」を押してください。
パスワードを忘れた場合の再設定機能はありません。このサービスではパスワードの再発行ができないので、登録時のパスワードは控えておいてください。

5ドメインを探す

トップページの検索ボックスに「.com より前の部分」だけを入れて「検索する」。ログインしなくても調べられます。

入力のきまり

  • 使えるのは半角英数字とハイフン（-）。全角で打っても自動で半角になります
  • 63 文字以内。ハイフンで始めたり終えたりはできません
  • 「.com」などの末尾（TLD）は入れません。1 回の検索で 22 種類すべての末尾を一度に調べます

結果の見方

末尾ごとに 1 マスずつ結果が並びます。「初年度が安い順」「更新が安い順」で並べ替え、「空きのみ表示」で絞り込めます。

表示意味できること
◯ 空きあり取得できます「申し込む」で申込フォームへ（要ログイン）
✕ 使用中すでに誰かが使っています「空いたら通知」で空き待ちに登録
？ 確認できませんでした一時的な通信エラーもう一度検索
⏳ 一時購入不可その末尾のレジストリにつながりにくい状態時間をおいて再検索。「空いたら通知」も可
🔧 メンテナンス中レジストリが点検中（終了予定が出ることがあります）終了後に再検索
− 取り扱いなしこの末尾は扱っていません—

どの末尾でも使われていたときは、「似ている候補」として別の名前や末尾を提案します。候補は表示前に空きを確かめてあります。

空いたら通知（空き待ち）

使用中などのドメインで「空いたら通知」を押すと空き待ちに登録され、購入できる状態になるとマイページにお知らせが出ます（料金はかからず、予約でもありません）。登録できるのは 1 人 10 件まで、30 日で自動的に解除されます。

料金（税込・1 年あたり）

初年度と 2 年目以降（更新）で料金が違います。長く使う予定なら更新料金で比べてください。

6ドメインを申し込む

検索結果の「申し込む」から。申込フォーム → 確認・支払い → 注文状況、の順に進みます。

  1. 1

    申込フォーム

    • 登録期間：1 / 2 / 3 / 5 年から選びます。合計金額がその場で変わります
    • 自動更新：チェックすると、期限が近づくと自動で 1 年ずつ更新されます（うっかり失効を防げるのでおすすめ）
    • くわしい設定（折りたたみ）：ふつうは触らなくて大丈夫です
      • ネームサーバ：「いまは設定しない」（おすすめ。取得後につなぐ設定から行えます）か、他社のネームサーバを 2 つまで指定
      • 認証コード（authInfo）：将来、他社へ移管するときに使う合言葉。自動生成されます（1〜64 文字で変更可）
      • コンタクト情報：登録者は会員本人。admin・tech・billing も同じにするのが既定です
  2. 2

    お申し込み内容の確認・支払い

    内容を確かめ、支払い方法を選びます。クレジットカード／コンビニ決済／銀行振込／口座振替／キャリア決済／QR コード決済／PayPal／Amazon Pay の 8 種類から選べますが、どれを選んでも疑似決済で、実際の請求は発生しません。「支払う（疑似決済）」を押すと注文が確定します（二重に押しても 2 回申し込まれることはありません）。

  3. 3

    注文状況

    表示意味
    ドメインの登録処理を行っています…処理中。ページを閉じても処理は続きます
    処理中です。自動で再試行しています。一時的な不調で再試行中。「お支払いが二重に発生することはありません」
    ドメインを取得しました完了。有効期限・認証コード・次の一歩（つなぐ設定／マイページ）が出ます
    処理できませんでした。失敗。「このご注文の料金が請求されることはありません」。時間をおいて再度どうぞ

    完了画面の認証コードは「他社への移管時に使用します。第三者には知られないようにしてください。」

取得直後のドメインは「まだインターネットに公開されていません」の状態です。ネームサーバ（DNS）を設定すると公開されます（9 章）。設定しなくてもドメインはあなたのものです。

ヘッダーの「マイページ」。持っているドメインの状態確認・期限の管理・各種設定の入口です。上から順に次のものが並びます（該当がなければ出ません）。

空き待ちのお知らせ空き待ち中のドメインが購入できるようになったとき。「購入手続きへ進む」。他の人が先に取ることもあるのでお早めに

8ドメインを管理する（詳細画面）

マイページでドメイン名を押すと詳細画面が開きます。カードごとに 1 つの操作です。

8.1 期限と更新

  • 「今すぐ更新する」→ 年数（1 / 2 / 3 / 5 年）を選ぶと、単価×年数と新しい有効期限が出ます。「支払って更新する」で疑似決済して完了。1 年ごとの更新は失効リスクが高いので、複数年まとめての更新がおすすめです。
  • 自動更新のスイッチもここにあります。OFF にすると「期限日に当サービスが廃止手続きを行い、ドメインは期限まで使ってそのまま終了します」。

8.2 保護・ロック設定

4 つのスイッチを個別に ON/OFF できます。うっかり操作や第三者による変更を防ぐためのものです。

ロックON にすると
移管ロック他社へ移管できなくなる（引っ越す前に OFF が必要）
変更ロックネームサーバなどの設定変更ができなくなる
削除ロック削除（解約）ができなくなる
更新ロック更新ができなくなる

8.3 移管用の認証コード（authInfo）

ふだんは伏せ字で表示され、コピーボタンで取り出せます。「再生成する」を押すと新しいコードに変わり、古いコードは使えなくなります。新しいコードはその場でクリップボードに入ります（できなかった場合はコピーボタンを使ってください）。第三者には教えないでください。

8.4 このドメインをもう使わない（解約）

2 つの選び方があります。

期限まで使って、そのあと自動で終わりにする（おすすめ）

  • 自動更新を OFF にするだけ。今すぐ止まらず、追加料金もありません

今すぐ削除する

  • 「このドメインを使っている Web サイトとメールが止まります」
  • 削除後 45 日間は復旧できます（復旧料金は 5 章参照）。過ぎると戻せず、数日で第三者が取得できる状態になります

解約手続き中はマイページと詳細画面に「あと N 日は戻せます」と「復旧する」が出ます。

9ドメインをつなぐ（DNS 設定）

取得したドメインをホームページやメールに結びつける設定です。詳細画面の「つなぐ設定をはじめる」から。質問に答えていく形で進みます。

先に用意しておくもの：ドメインは「名前」だけです。見せたい中身（ホームページを置くサービス＝ホスティング、あるいはメールサービス）は別に契約が必要で、その契約先から届いた「設定案内」を手元に開いておきます。
  1. 1

    「このドメインを、何に使いますか？」

    ホームページを見せたい／メールで使いたい／まだ何も用意していない、から選びます。「まだ何も用意していない」を選ぶと設定画面ではなく準備ガイドが出ます（例：Wix・STUDIO・Vercel・GitHub Pages・エックスサーバー、メールなら Google Workspace・Microsoft 365 など）。何も設定せず閉じてもドメインはあなたのものです。

  2. 2

    「案内に書いてあるのは、どちらですか？」

    • 「ns1.〜」のような文字列が 2 つ → ネームサーバを変更する方式（ステップ 3A）
    • 数字の IP アドレスや案内先のホスト名 → レコードを入力する方式（ステップ 3B）
    • 分からない → 見分け方の説明が出て、安全な 3B に進みます
  3. 3A

    ネームサーバを変更する

    案内どおりのホスト名を 2 つ（2 つ目は任意）入力します。必ず次の注意が出ます：「ネームサーバーを変更すると、このサービスで設定した DNS レコードは無効になります。メールも止まります。」反映には通常数分、長いと 48 時間ほどかかります。

  4. 3B

    レコードを入力する

    入れ方は 3 通り：テンプレートから選ぶ（有名なサービスを選ぶと自動で埋まる）／案内文を貼り付ける（設定案内の文章を貼ると読み取る）／自分で入力する（A・AAAA・CNAME・MX・TXT・NS の各レコード）。保存するとそのドメインの設定がまるごと置き換わるので、確認画面の内容をよく見てください。空のまま保存すると設定がすべて消えます。

  5. 4

    「つながったか確認する」

    保存した内容が実際に返ってきているかを、このサービスの DNS で確かめます（未設定／反映待ち／確認できました／食い違いあり の 4 状態）。ネームサーバを他社に向けている場合は、ここで保存した内容は公開には使われない旨が表示されます。

すでにネームサーバの値を持っている人は、詳細画面の「ネームサーバーを変更」から直接変更できます。

10移管（引っ越し）

他社からこのサービスへ持ってくる（移管する）

マイページの「移管する」から。

  1. 今そのドメインを管理している会社（移管元）の管理画面にログインします。
  2. 「AuthCode」「認証コード」「移管コード」などの名前のコードを発行・表示します。見つからないときは移管元のヘルプで「移管」「AuthCode」を検索してください。移管ロックが有効なら先に移管元で解除が必要です。
  3. 表示されたコードをコピーして、フォームの入力欄に貼り付けて申請します。

申請後はマイページに「移管元の承認待ちです」と出ます。承認されると自動でドメイン一覧に追加されます（反映まで少し時間がかかることがあります）。「移管元がこの申請を承認しませんでした」と出たら、AuthCode や移管ロックの状態を移管元で確認して再申請してください。待っている間は「申請を取り下げる」ができます。

このサービスから他社へ出す

  1. 詳細画面で「移管ロック」を OFF にします。
  2. 「移管用の認証コード（authInfo）」をコピーして、移管先の会社に入力します。
  3. 移管先が申請すると、マイページに「移管申請が来ています」が出るので「承認して移管する」を押します（取り消せません）。20 分間なにもしないと自動で承認されます。心当たりがなければ「拒否する」を押してください。

15これは何？

Web サービスに新しくアカウントを作るとき、「メールに届いた 6 桁のコードを入力してください」という画面をよく見かけます。Zerokara Domain（ドメイン登録サービス）にもこの仕組みがあり、Zerokara Mail はその認証コードを"受信箱"のような画面で見られるようにした閲覧専用アプリです。

本物のメールは送りません。データベースには 6 桁のコードだけが保存されていて、送信元・件名・本文はこのアプリが決まった文面をあてはめて表示しています。

できること

  • 登録したメールアドレス宛の認証コードを一覧で見る
  • コードをワンクリックでコピーする
  • コードが発行・再発行されたら自動で画面に反映する
  • 「期限切れ」「認証済み」などの状態を確かめる
  • 認証が終わって消えたコードも、5 日間は控えを表示する

できないこと

  • メールを送る・返信する・削除する（ボタンは飾りです）
  • 認証コードを作る・入力して認証する（発行側アプリの役目）
  • 登録中の全アドレスを一覧する（安全のため禁止されています）
  • ログイン（アクセス制御は置き場所側で行います）

20使い方

20.1 メールアドレスを登録する

  1. 1

    サイドバーの「表示するアドレス」の入力欄に、確認したいメールアドレスを入れる

    受信トレイの上に「認証コードを表示するには…」の案内バーが出ているときは、その「アドレスを追加」ボタンを押しても入力欄に移動できます。

  2. 2

    「追加」を押す（または Enter）

    大文字・小文字や前後の空白は自動でそろえられます（Taro@Example.COM → taro@example.com）。形式が違うときや登録済みのときは、その場に赤い文字で理由が出ます。

  3. 3

    アドレスの横に状態が出る

    コードあり なら受信トレイに 1 通届いています。未発行 は、そのアドレスにまだコードが作られていないだけなので、発行側アプリで登録操作をすると自動で届きます。

登録したアドレスはブラウザに記憶され、次に開いたときも残っています。何件でも登録できます。

20.2 コードを確認する・コピーする

コピーの方法は 3 つあり、どれも結果は画面下のトースト（小さな通知）か、ボタンの文字で知らせます。

場所操作向いている場面
一覧の行の右端コピーアイコンをクリックいちばん速い。メールを開く必要がありません
詳細画面の右上「コードをコピー」ボタン本文を読んでからコピーしたいとき
本文の大きなコード数字そのものをクリックスマホなど、ボタンが小さく感じるとき

コピーできたら、発行側アプリの入力欄に貼り付けて認証を進めてください。

20.3 メールを開く・戻る

  • 一覧の行をクリックすると本文が開き、そのメールは既読になります（薄緑の背景と太字が消えます）。
  • 戻るには左上の「←」か、キーボードの Esc。
  • 詳細画面には宛先（To:）、送信日時、有効期限、状態ラベルが並びます。

20.4 探す・絞り込む

上部の検索ボックスに文字を入れると、その場で一覧が絞られます。メールアドレスの一部、件名、コードの数字、どれでも構いません。大文字・小文字は区別しません。消せば元に戻ります。

20.5 アドレスをやめる

サイドバーのアドレス右端の「×」を押すと一覧から外れ、そのアドレスのメールも受信トレイから消えます。ブラウザに控えていたコードも同時に消えるので、また見たいときは追加し直してください（発行側で消えていれば「未発行」に戻ります）。

20.6 URL でアドレスを渡す

次のように ?email= を付けて開くと、そのアドレスが登録された状態で始まります。同じ端末で何度も使うときや、リンクを共有するときに便利です。

http://localhost:5173/?email=taro@example.com&email=hanako@example.com

20.7 スマホ・狭い画面で使う

幅が狭いとサイドバーは隠れます。左上の「≡」で開き、背景をタップするか Esc で閉じます。一覧の抜粋文は省略されますが、行を開けば本文はすべて読めます。

22知っておくこと

  • 自動で更新されます。発行側でコードが作られたり作り直されたりすると、再読み込みしなくても画面に出ます。
  • 認証が終わるとコードは発行側で削除されます。それでも受信トレイから消えないよう、このアプリは表示できたコードをブラウザに控え、保存済み として 5 日間表示し続けます。
  • 既読・アドレス・控えは、そのブラウザの中だけの情報です。別の PC や別のブラウザには引き継がれません。データベースには何も書き込みません。
  • ダミーメールが 4 通まざっています。「Zerokara Cloud」「請求サポート」「サンプル通信」「勉強会事務局」からのメールは受信箱らしく見せるための架空のもので、常に既読、コピーボタンもありません。
  • 表示されるメールの文面は固定です。送信者は no-reply <support@zerokaradomain.com>、件名は「Zerokara Domainのアカウント認証」で、コードの部分だけがデータベースの値に置き換わります。

23困ったとき

症状から探してください。多くはエミュレータの起動状態か、プロジェクト ID の食い違いです。

taro / hanako / jiro / saburo という 4 件のメールが出る

データベースにつながらなかったので、練習用のダミーデータ（モック）を表示しています。ブラウザのコンソールに「モックデータを表示します」と理由が出ています。

発行側アプリのエミュレータが起動しているか確かめて、起動したらヘッダーの再読み込みボタンを押します。.env を置いている場合は、その値が雛形（your_...）のままになっていないかも見てください。

アドレスを追加したのに、ずっと「未発行」のまま

（1）まだ発行側で登録操作をしていない。（2）エミュレータにはつながっているが、プロジェクト ID が発行側と違うため、別の空っぽの箱を見ている。（3）発行側で登録したアドレスと綴りが違う。

コンソールの project: が demo-teamc-2026（発行側の --project と同じ）か確認します。違うときは .env の VITE_FIREBASE_PROJECT_ID を直すか、.env を消して既定値に戻します。綴りを見直し、発行側で認証コードを発行してみてください。

「取得できません」と赤く出る

エミュレータが途中で止まった、ポートが違う、またはセキュリティルールで読み取りが拒否されています。

エミュレータを起動し直し、再読み込みボタンを押します。コンソールに PERMISSION_DENIED が出ている場合は、発行側のルールで get が許可されているかを開発者に確認してください。

「コピーできません」と出る

ブラウザがクリップボードへの書き込みを許可していません。http://localhost 以外のアドレス（http://192.168.… など）で開くと、多くのブラウザは安全のためコピーを止めます。

http://localhost:5173/ で開き直します。それでも駄目なときは、詳細画面の大きな数字をドラッグして手動でコピーしてください。

認証が終わったらメールが消えた／「保存済み」が消えた

認証済みのコードは発行側で削除され、このアプリは控えを 5 日間だけ表示します。5 日を過ぎたか、アドレスを × で外したか、別のブラウザで開いています。

仕様どおりの動きです。新しいコードが必要なら発行側アプリで再発行してください。

npm run dev で「Port 5173 is in use」と出る

前回のサーバーが残っているか、別のアプリが同じポートを使っています。

Vite は自動で 5174 など次のポートを使うので、ターミナルに表示された URL を開けば大丈夫です。古いサーバーを止めるには、そのターミナルで Ctrl + C。

画面が真っ白／何も表示されない

npm install がまだ、または途中で失敗しています。もしくは古いブラウザです。

ターミナルのエラーを確認し、npm install をやり直してから npm run dev。F12 のコンソールに赤いエラーがあれば、その文面を開発者に伝えてください。

ダークモードになる／色が変わった

OS の外観設定（ダーク／ライト）に自動で合わせています。

不具合ではありません。OS の設定を変えれば追従します。

24別の環境につなぐ

ふだんの開発では設定ファイルは不要です。本番の Firebase や、別のエミュレータを見たいときだけ .env を作ります。

  1. 1

    雛形をコピーする

    $ cp .env.example .env
  2. 2

    .env を開いて値を入れる

    別のエミュレータに向けるなら、次の 3 行だけで足ります。

    VITE_FIREBASE_PROJECT_ID=<エミュレータのプロジェクトID>
VITE_FIREBASE_API_KEY=dummy-key
VITE_FIRESTORE_EMULATOR_HOST=127.0.0.1:8080

    本番の Firebase に向けるなら、Firebase コンソール →「プロジェクトの設定」→「マイアプリ」の値を VITE_FIREBASE_API_KEY などに転記し、エミュレータの行は書きません。

  3. 3

    サーバーを立ち上げ直す

    .env は起動時にしか読まれません。Ctrl + C で止めてから、もう一度 npm run dev。

変数意味
VITE_DB_KINDfirestore（既定）か realtime。データベースの種類
VITE_FIREBASE_PROJECT_IDプロジェクト ID。これを書くと開発時の既定（エミュレータ）は使われなくなる
VITE_FIREBASE_API_KEY ほかFirebase コンソールの値。エミュレータ相手ならダミーで可
VITE_FIREBASE_COLLECTIONコードが入っている場所の名前（既定 verificationCodes）
VITE_FIRESTORE_EMULATOR_HOSTエミュレータの host:port。Realtime DB なら VITE_DATABASE_EMULATOR_HOST
VITE_GA_MEASUREMENT_IDGoogle Analytics の測定 ID。書いたときだけ計測する
.env には秘密の値が入るので、Git にコミットしないでください（.gitignore で除外済み）。共有してよいのは雛形の .env.example だけです。

├─ ui.ts        # 描画：DOM 組み立て（一覧・詳細・トースト）

docs/
├─ SPEC.md        # 画面・動作の仕様

データの読み方で守ること

  • 認証コードは verificationCodes/{メールアドレス} に 1 アドレス 1 件。ドキュメント ID は trim + 小文字化 したアドレス。
  • 発行側のルールは get のみ許可、list と write は禁止。コレクションを一覧取得すると PERMISSION_DENIED (false for 'list') になるので、必ず getDoc / ドキュメント単位の onSnapshot で 1 件ずつ読む。
  • 読むフィールドは code（otp / value も可）、日時は updatedAt → createdAt → created_at → timestamp の順、ほかに expiresAt と verified。
  • firebase init はこのリポジトリでは行わない（ルール・Functions は発行側が持つ。誤って同じプロジェクトにルールをデプロイする事故を防ぐため）。
  • 発行側のルールを変えたら、E2E 用の写し tests/e2e/firestore.rules も追随させる。

エミュレータの中身を直接確かめたいときは、管理者権限で REST を叩けます。

$ curl -s -X POST "http://127.0.0.1:8080/v1/projects/demo-teamc-2026/databases/(default)/documents:listCollectionIds" \
    -H "Authorization: Bearer owner" -H "Content-Type: application/json" -d '{}'

26注意事項

認証コードは秘密の情報です。このアプリはインターネットに一般公開せず、社内ネットワークや開発環境など、アクセスが制限された場所でだけ使ってください。
共用の PC では使わないでください。受け取ったコードはブラウザの localStorage に平文で最大 5 日間残ります。使い終わったらアドレスを × で外すと、控えも一緒に消えます。
  • アクセス解析（GA4）は測定 ID を設定したときだけ動き、URL の ?email= 部分は送信しません。同意取得が必要な地域で公開する場合は別途対応が要ります。
  • Gmail のロゴや名称は使っていません（独自の封筒アイコンと「Zerokara Mail」という名前です）。
  • 本文の見た目は Web 表示用です。実際にメールとして配信する場合は、別途メール用のテンプレートが必要になります。
